## Backend

The reviewed Python 3.11 release lock pins PyMuPDF 1.28.2. It is imported by:

- `backend/app/services/extraction/pdf_extractor.py` for PDF text and page rendering.
- `backend/app/services/synthesis/exporting.py` for PDF export.

PyMuPDF's upstream licensing information identifies GNU AGPL v3 and an Artifex commercial license as its licensing options. PyMuPDF4LLM is not present in `backend/requirements-release.lock`. The Docker backend and worker builds install the pinned PyMuPDF wheel, so those built images include it. Preserve PyMuPDF/MuPDF license and copyright notices with the distributed software. The reviewed upstream documentation describes PDF metadata fields, but did not identify a requirement to insert a PyMuPDF copyright or producer string into PDFs generated by the application. A local export smoke check found empty Producer/Creator/Title metadata; do not add a misleading output attribution without confirming it is required. This is a source review, not a legal opinion; obtain Artifex clarification if the distribution grant or output attribution remains uncertain. See [the exact 1.28.2 release](https://github.com/pymupdf/PyMuPDF/releases/tag/1.28.2), [PyMuPDF licensing](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright), [PyMuPDF metadata documentation](https://pymupdf.readthedocs.io/en/latest/document.html#Document.metadata), [Artifex licensing](https://artifex.com/licensing), and [GNU AGPL v3](https://www.gnu.org/licenses/agpl-3.0.html).

Other prominent locked backend components include FastAPI 0.141.1, SQLAlchemy 2.1.0, psycopg 3.3.6, ONNX Runtime 1.30.0, RapidOCR ONNX Runtime 1.4.4, and Python-docx 1.2.0. Package metadata reported permissive license families for the reviewed installed set; two distributions (`colorama` 0.4.6 and `setuptools`) did not provide license metadata in that inspection. A release distributor should retain upstream license/notice files and generate a version-specific SBOM from the actual build rather than treating this abbreviated note as a substitute.

## Network service and container distribution

GNU's AGPL guidance says users remotely interacting with a modified version must be offered its corresponding source, and AGPL §5(d) defines appropriate legal notices for interactive user interfaces when conveying a covered work. A public source repository and release archive should remain available for the exact deployed version, including build/install/run scripts and applicable release lock files. Docker images distributed separately need an equivalent source offer and clear directions. The current frontend contains no legal-notice/source control, and no public source URL is available. Treat public hosted operation or distribution as blocked until the exact source offer and appropriate UI notice are implemented or the licensing treatment is confirmed by qualified counsel. See [GNU AGPL v3](https://www.gnu.org/licenses/agpl-3.0.html), [GNU FAQ on AGPL network source](https://www.gnu.org/licenses/gpl-faq.en.html#AGPLv3InteractingRemotely), and [GNU guidance on using GNU licenses](https://www.gnu.org/licenses/gpl-howto.en.html).
